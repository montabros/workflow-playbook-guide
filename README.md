# 新しいワークフロー作業書（プレイブック）の作り方

複数の公式ワークフロー（プレイブック）を組み合わせて、自分の目的に合った新しい作業書を作るための手順書。
出典: Paul Ponna「Make LONG AI Videos FREE & UNLIMITED (No Watermark)」（2026-10-16配信）の方法と、自分たちの制作経験から作成。

## 考え方

- 作業書はチャットではなくGitHubに置く。チャットは要約・圧縮されて指示が欠けていくが、リポジトリは残り続ける。
- 1つのワークフロー = 1つのリポジトリ。中身は SYSTEM_PROMPT.md（階層化した指示）、README、examples（真似させたい事例）、evals（やってはいけないことのルール）。
- AIアシスタント（Claude / ChatGPT など）の役割は、作業書を読み、ブラウザで VideoExpress を操作して動画を作ること。この手順書どおりに作れば、どのAIでも同じ作業ができる。

- ベースにできる公式プレイブックは github.com/ai-playbooks にあり、自分のアカウントへフォークして使う（2026-11-06時点で13件中10件をフォーク済み）。
- 制作には VideoExpress（All Access）と CloneVoice を使う。

## 手順

### 1. ベースにするワークフローを2つ選ぶ

目的から逆算して選ぶ。組み合わせの例:

- 歴史ドキュメンタリー × Stickman: 解説の型はドキュメンタリー、見た目はStickmanにする
- 2キャラクター動画 × First Frame / Last Frame: 対話劇の型に、カット間の連結（前シーンの終了画像を次シーンの開始画像にする）を足す
- キッズ音楽動画 × Viral Shorts: 歌の型に、冒頭のフックとループ構造を足す

### 2. 各リポジトリから「残す要素」と「捨てる要素」を決める

各フォークの SYSTEM_PROMPT.md を開き、要素ごとにメモする（語り手・声、映像スタイル、比率、シーン構成、音楽、禁止事項）。このメモが組み合わせ指示の元になる。

### 3. AIに組み合わせを指示する

ポイント:

- 「Aの○○は好き、Bの作り方は好きではない」のように、残すものと捨てるものを明示する
- 出力は「新しいGitHubリポジトリ + 再利用できるシステムプロンプト」の形で頼む
- 入力と出力をはっきりさせる（例: 入力 = 自分のスポークスマン動画、出力 = VideoExpressのシーン映像）

文例は下の「組み合わせ指示のテンプレート」を参照。

### 4. 階層を再構成する

システムプロンプトは1枚の文章ではなく章立てにする:
目的 / 入力 / キャラクター / 声と音楽 / カメラ / 比率と長さ / 制作手順 / 禁止事項（evals） / 完了条件。

縦型にする場合は「縦型にして」と言うだけでは足りない。9:16専用の構図ルール（単なる切り抜きではなく縦型の構図で作る、長さは1分未満が望ましい等）を追加し、別ワークフローとして保存する。

### 5. examples を自分の事例に入れ替える

公式の事例のままだと他の人のコピーと同じになる。自分の好みの動画や、過去の成功作を事例に入れる。

### 6. evals（やってはいけないこと）を必ず書く

自分たちの制作で実際に起きた失敗をルール化する。記入例:

- 資産はタイトルやサイズではなく、詳細IDで特定する（同名・同サイズの取り違え防止）
- 明るさの判定は開始画像ではなく、実際の動画フレームで行う
- 暗転した後のシーンを明るくしない（明るさの流れを先に決める）
- 手がかり（小道具）は観客に見せ、登場人物は気づかず素通りさせる。気づくのは決めた場面だけにする
- 冷蔵庫のような小道具は、固定の説明文言を全シーンで一字一句そろえる

### 7. 新しいリポジトリとして保存する

- 名前は目的が分かる英語の小文字 + ハイフン（例: documentary-stickman-playbook）
- README に「目的・入力・出力・使うAI・使うアプリ」を書く
- 本文（指示書）は SYSTEM_PROMPT.md に置く

### 8. 使うとき

新しいリポジトリのURL（または SYSTEM_PROMPT.md の中身）をAIアシスタントに渡す。AIはブラウザで VideoExpress を開き、作業書どおりに生成・結合する。

- 1回の生成の上限は300秒。長くする場合は「物語を続けて、整合性を保って延長して」と指示し、クリップを足していく
- 完成したら、改良点はチャットではなくリポジトリ側に反映する

## 組み合わせ指示のテンプレート

「（AのリポジトリURL）と（BのリポジトリURL）を使って、新しいプレイブックを作って。Aの［残したい要素］は好きだが、［捨てたい要素］は使わない。［変更点］にして、新しいGitHubリポジトリと、再利用できるシステムプロンプトを作って。」

## 注意

- 「無料・無制限」は手順書の配布が無料という意味。VideoExpress本体は買い切りの有料アプリで、生成はそのアカウントの枠で行う
- 公式ワークフローのコピーをそのまま使わず、必ず自分の目的に合わせて改変する（全員が同じ出力になるのを避けるため）
- モデルやツールの名前は変わり得る。作業書はリポジトリのURLで参照すれば、AIが変わっても使い続けられる
